# سند مشخصات فنی — Zero

**لایه ورودی گفتاری برای ویندوز**

نسخه سند: 1.0 — پیش‌نویس برای تیم توسعه
وضعیت: آماده بازبینی
مخاطب: تیم فنی (دسکتاپ، بک‌اند، هوش مصنوعی) و مدیر محصول

---

## ۱. خلاصه اجرایی

Zero یک لایه ورودی گفتاری سراسری برای ویندوز است: کاربر در هر برنامه‌ای که Cursor داشته باشد، با یک میانبر صحبت می‌کند و متن همان‌جا درج می‌شود. محصول از دو پروسه دسکتاپ (Daemon همیشه‌روشن و Studio بنابه‌نیاز)، یک موتور تبدیل هیبرید (ابری با پشتیبان محلی) و یک سرور Gateway چندتأمین‌کننده تشکیل شده است.

**قول‌های غیرقابل مذاکره محصول:**

| قول | سنجه |
|---|---|
| نامرئی بودن | مصرف رم Daemon در حالت بیکار < ۵۰ مگابایت (هدف: ۲۰) |
| فوری بودن | از پایان صحبت تا ظهور متن < ۱ ثانیه (P95) |
| گم‌نشدن گفتار | هیچ صحبت ضبط‌شده‌ای تحت هیچ شرایطی از بین نمی‌رود |
| رازداری | حالت Local هیچ بایتی به شبکه نمی‌فرستد؛ لیست سیاه در سطح Hotkey اعمال می‌شود |
| فارسی حرفه‌ای | نیم‌فاصله، رسم‌الخط و نگارش صحیح به‌عنوان مزیت رقابتی اصلی |

**دامنه نسخه ۱ (فصل Core):** میانبر سراسری، ضبط و تبدیل، درج هوشمند سه‌استراتژیک، Overlay زبان بدن، Clipboard Mode، History ده‌تایی، حالت آفلاین، لیست سیاه، سهمیه فریمیوم.

**خارج از دامنه نسخه ۱:** لایه صیقل (Smart)، Context Awareness، واژه‌نامه شخصی، Draft Mode، فرمان‌های صوتی (Flow)، پشتیبانی macOS/Linux. معماری باید جای این‌ها را باز بگذارد ولی پیاده‌سازی نشوند.

## ۲. معماری کلان

### ۲.۱. نقشه اجزا

```
┌────────────────────────── کلاینت ویندوز ──────────────────────────┐
│                                                                    │
│  Zero Daemon (Rust خالص، همیشه‌روشن)                               │
│  ├── Hotkey Listener        (نگهبان)                               │
│  ├── Audio Capture          (گوش)                                  │
│  ├── Engine Router          (داور: ابری/محلی)                      │
│  │     ├── Cloud Client ──── WebSocket ──► Gateway                 │
│  │     └── Local Engine ──── whisper.cpp (اختیاری)                 │
│  ├── Text Injector          (قلم: سه استراتژی)                     │

│  ├── Auth & Licensing        (حساب، اشتراک، JWT)                    │

│  └── PostgreSQL + Redis                                             │
└─────────────────────────────────────────────────────────────────────┘
```

### ۲.۲. چرا دو پروسه؟

- **Daemon** هیچ WebView ندارد؛ فقط Rust و APIهای Win32. نتیجه: رم زیر ۲۰ مگابایت، راه‌اندازی زیر ۱۵۰ میلی‌ثانیه، و پایداری بالا (کرش UI هرگز میکروفون و درج را نمی‌اندازد).
- **Studio** یک اپ Tauri کامل است که فقط با کلیک کاربر روی آیکون Tray یا از داخل Onboarding باز می‌شود و با بسته‌شدن، کامل از رم خارج می‌شود.
- ارتباط این دو از طریق IPC محلی (Named Pipe ویندوز) با یک پروتکل پیام ساده JSON انجام می‌شود. Studio هرگز مستقیم به میکروفون یا سرور STT دست نمی‌زند؛ همه‌چیز از Daemon عبور می‌کند تا منبع حقیقت یکی باشد.

### ۲.۳. اصول معماری

1. **Crash-only design:** Daemon باید بتواند در هر لحظه کشته و دوباره اجرا شود بدون از دست رفتن داده. هر صدای درحال‌ضبط قبل از پردازش روی دیسک است.
2. **Offline-first برای داده محلی:** تنظیمات، History و واژه‌نامه در SQLite محلی‌اند؛ سرور فقط برای STT ابری، حساب و سهمیه است.
3. **کلاینت هرگز کلید Provider ندارد:** تمام ترافیک STT ابری از Gateway خودمان عبور می‌کند.
4. **هر قابلیت هوشمند، خاموش‌شدنی است:** هیچ رفتار «جادویی» بدون کلید خاموش/روشن در تنظیمات وجود ندارد.

## ۳. Zero Daemon — مشخصات اجزا

### ۳.۱. Hotkey Listener (نگهبان)

- ثبت میانبر سراسری از طریق `RegisterHotKey` در Win32؛ در صورت تعارض با میانبر رزروشده سیستم یا برنامه دیگر، هنگام ثبت خطا برگردانده می‌شود و Studio به کاربر پیشنهاد کلید جایگزین می‌دهد.
- دو حالت تعامل: **Tap-to-Talk** (زدن = شروع، زدن دوباره = پایان) و **Push-to-Talk** (نگه‌داشتن = ضبط). حالت PTT از طریق هوک کیبورد سطح پایین (`WH_KEYBOARD_LL`) رویداد KeyUp را تشخیص می‌دهد.
- **قانون لیست سیاه:** پیش از هر واکنش به میانبر، پنجره فعال (`GetForegroundWindow` → نام پروسه) با لیست سیاه مقایسه می‌شود. اگر در لیست بود، رویداد نادیده گرفته می‌شود و میکروفون هرگز باز نمی‌شود. این تنها نقطه اعمال لیست سیاه است تا هیچ مسیر دورزدنی وجود نداشته باشد.
- محافظ ضدلرزش: فاصله دو رویداد میانبر کمتر از ۱۵۰ میلی‌ثانیه نادیده گرفته می‌شود.

### ۳.۲. Snapshot مقصد (عکس فوری)

در لحظه شروع ضبط — نه پایان — این اطلاعات ثبت می‌شود:

- هندل پنجره فعال و نام پروسه
- عنصر متنی دارای فوکوس از طریق UI Automation (در صورت وجود) و اینکه قابل‌ویرایش است یا نه
- وضعیت RTL/LTR کنترل مقصد (در حد قابل تشخیص)

اگر کاربر حین صحبت پنجره را عوض کند، متن به مقصدِ Snapshot می‌رود، نه پنجره فعلی. اگر مقصد Snapshot دیگر وجود نداشته باشد (پنجره بسته شده)، سقوط به Clipboard Mode + اعلان «کپی شد».

### ۳.۳. Audio Capture (گوش)

- دریافت صدا از دستگاه پیش‌فرض ورودی از طریق WASAPI در حالت اشتراکی؛ فرمت داخلی 16kHz mono PCM (استاندارد ورودی Whisper و اکثر Providerها).
- **بافر دیسک (قول گم‌نشدن):** همزمان با استریم، صدا در فایل موقت رمزگذاری‌شده در `%LOCALAPPDATA%\Zero\tmp` نوشته می‌شود. پس از تحویل موفق متن، فایل حذف امن می‌شود؛ در صورت شکست، برای بازیابی باقی می‌ماند.
- سقف مدت یک ضبط در نسخه ۱: **۵ دقیقه** (پس از آن ضبط بسته و پردازش می‌شود؛ Overlay هشدار ملایم می‌دهد).
- تشخیص سکوت (VAD سبک سمت کلاینت) فقط برای دو کار: برش سکوت ابتدای ضبط، و پیشنهاد خودکار پایان در حالت Tap اگر ۴ ثانیه سکوت ممتد بود (قابل خاموش‌کردن).
- اگر هیچ میکروفونی در دسترس نبود: Overlay قرمز + پیام «میکروفون پیدا نشد» و بازکردن مستقیم تنظیمات صدای ویندوز با یک کلیک.

### ۳.۴. Engine Router (داور)

جدول تصمیم به این ترتیب ارزیابی می‌شود:

| شرط | مسیر |
|---|---|
| کاربر حالت «فقط محلی» را انتخاب کرده | Local |
| اتصال Gateway برقرار نیست (Health-check دوره‌ای) | Local اگر نصب است؛ وگرنه «صف تأخیری» |
| سهمیه ابری تمام شده (کاربر رایگان) | Local اگر نصب است؛ وگرنه پیشنهاد ارتقا + صف تأخیری |
| در غیر این صورت | Cloud |

- **صف تأخیری:** فایل صوتی نگه داشته می‌شود و به‌محض برقراری شرایط، تبدیل و نتیجه در History قرار می‌گیرد + اعلان. (درج خودکار انجام نمی‌شود چون زمینه کاربر عوض شده است.)
- **سوییچ وسط ضبط:** اگر اتصال ابری حین استریم قطع شد، ضبط ادامه می‌یابد (بافر دیسک)، و کل فایل پس از پایان به موتور محلی داده می‌شود. متن جزئیِ دریافت‌شده از ابر دور ریخته می‌شود تا دوگانگی پیش نیاید؛ سادگی بر بهینگی مقدم است.

### ۳.۵. موتور محلی

- whisper.cpp با مدل چندزبانه کوچک کوانتیزه‌شده؛ **دو سطح دانلود اختیاری** از داخل Studio: «سبک» (حدود ۱۰۰–۲۰۰ مگابایت، سریع) و «دقیق» (حدود ۵۰۰ مگابایت تا ۱ گیگابایت). نصب اولیه برنامه بدون هیچ مدلی است تا زیر ۱۰ مگابایت بماند.
- اجرا روی CPU به‌صورت پیش‌فرض؛ شناسایی و استفاده از GPU (Vulkan/CUDA) در صورت وجود، به‌عنوان بهبود فاز بعد.
- بارگذاری مدل به‌صورت Lazy در اولین استفاده و تخلیه از رم پس از ۵ دقیقه بی‌استفادگی (قابل تنظیم) — تا قول رم حالت بیکار حفظ شود.

### ۳.۶. Cloud Client

- اتصال WebSocket پایدار به Gateway با احراز هویت JWT؛ اتصال فقط هنگام نیاز باز می‌شود و پس از ۶۰ ثانیه بیکاری بسته می‌شود.
- استریم تکه‌های صوتی (Chunkهای حدود ۲۰۰–۳۰۰ میلی‌ثانیه) و دریافت متن جزئی (partial) و نهایی (final).
- Backpressure: اگر ارسال از دریافت عقب افتاد، تکه‌ها روی دیسک صف می‌شوند؛ هرگز صدا حذف نمی‌شود.

### ۳.۷. Text Injector (قلم)

استراتژی‌ها به ترتیب، با سقوط بی‌صدا به بعدی:

1. **UI Automation (ترجیحی):** درج از طریق الگوهای `TextPattern`/`ValuePattern` روی عنصر Snapshot. تمیزترین راه؛ Undo برنامه مقصد هم درست کار می‌کند.
2. **شبیه‌سازی کیبورد:** ارسال متن با `SendInput` به‌صورت رویدادهای Unicode (نه Scan Code) تا مستقل از زبان کیبورد کاربر باشد. نرخ ارسال کنترل‌شده (حدود ۲۰۰–۴۰۰ کاراکتر بر ثانیه) برای برنامه‌های کند.
3. **Clipboard + Paste:** ذخیره محتوای فعلی Clipboard → قرار دادن متن → ارسال Ctrl+V → **بازگرداندن محتوای قبلی Clipboard** پس از ۳۰۰ میلی‌ثانیه. اگر پنجره مقصد Paste را نپذیرفت، متن در Clipboard می‌ماند و اعلان «کپی شد» نمایش داده می‌شود.

قواعد مکمل:

- اگر Snapshot گفته بود «مقصد قابل‌تایپ نیست»، مستقیم به Clipboard Mode می‌رویم بدون تلاش برای درج.
- **RTL:** متن همیشه به‌صورت رشته Unicode کامل (با نویسه‌های فارسی استاندارد و نیم‌فاصله U+200C) ارسال می‌شود؛ هیچ منطق معکوس‌سازی دستی وجود ندارد. برای برنامه‌هایی که شناخته‌شده RTL را خراب می‌کنند (لیست نگه‌داری‌شده در تنظیمات Remote Config)، به استراتژی Clipboard سقوط می‌کنیم چون Paste معمولاً سالم‌تر از شبیه‌سازی تایپ است.
- **صف درخواست‌ها:** حداکثر یک درج در لحظه؛ درخواست‌های جدید FIFO پشت سر هم. عمق صف ۳؛ بیشتر از آن، قدیمی‌ترین به History می‌رود.

### ۳.۸. Overlay Renderer (چهره)

- پنجره لایه‌ای (`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW`): بدون فوکوس، Click-Through، بدون حضور در Alt-Tab.
- دایره ۳۶ پیکسلی (مقیاس‌پذیر با DPI) که با فاصله ثابت از Cursor حرکت می‌کند؛ نرخ به‌روزرسانی موقعیت ۳۰ فریم بر ثانیه فقط حین فعال بودن.
- چهار حالت: آبی نبض‌دار (شنیدن)، زرد چرخان (تبدیل)، سبز (موفق، ۵۰۰ میلی‌ثانیه و محو)، قرمز (خطا + یک خط متن؛ کلیک روی آن استثنائاً فعال می‌شود و جزئیات/راه‌حل را باز می‌کند).
- حالت جایگزین «ویجت گوشه» (سناریوی ۴ سند محصول): همان چهار حالت در یک ویجت ثابت قابل‌جابه‌جایی؛ انتخاب بین دو سبک در تنظیمات.
- در Silent Mode هیچ صدایی پخش نمی‌شود؛ بازخورد فقط بصری است. (پیش‌فرض: بدون صدا.)

### ۳.۹. State Store

- SQLite در `%LOCALAPPDATA%\Zero\zero.db` شامل: تنظیمات، History (۱۰ رکورد آخر متنی؛ صدا ذخیره نمی‌شود مگر کاربر فعال کند)، لیست سیاه، آمار مصرف محلی.
- رمزگذاری فیلدهای متنی History با کلید مشتق‌شده از DPAPI ویندوز (وابسته به حساب کاربر ویندوز).
- «پاک‌کردن همه داده‌ها» با یک دکمه در Studio: حذف DB، فایل‌های tmp و مدل‌های دانلودشده.

## ۴. Zero Studio — مشخصات

- اپ Tauri (WebView2) با فرانت سبک؛ تک‌پنجره با پنج بخش: تنظیمات (پیش‌فرض)، History، واژه‌نامه (فاز ۲ — فقط جای منو رزرو)، حساب، درباره.
- Onboarding سی‌ثانیه‌ای در اولین اجرا: انتخاب میانبر → تست زنده («سلام دنیا») → انتخاب حالت موتور → پایان. بدون ساخت حساب اجباری؛ حساب فقط برای سهمیه ابری لازم است و می‌تواند به بعد موکول شود (حالت مهمان = فقط محلی).
- Studio از طریق Named Pipe با Daemon حرف می‌زند؛ پیام‌های اصلی: `get/set settings`, `get history`, `test-mic`, `download-model`, `login`, `usage`.
- اگر Daemon در حال اجرا نباشد، Studio آن را اجرا می‌کند (و برعکس هرگز).

## ۵. سرور — مشخصات

### ۵.۱. Auth & Licensing
- ثبت‌نام با ایمیل/OTP یا ورود گوگل؛ JWT کوتاه‌عمر + Refresh Token برای Daemon.
- جدول اشتراک: `free` و `smart`؛ منبع حقیقت وضعیت اشتراک سرور است و کلاینت فقط کش ۲۴ساعته دارد (تا قطعی سرور، کاربر پولی را قفل نکند).

### ۵.۲. Quota Service
- واحد شمارش: ثانیه صوتِ ارسال‌شده به Provider (نه طول متن).
- شمارنده در Redis با کلید `quota:{userId}:{yyyymm}` و تخلیه دوره‌ای به PostgreSQL برای گزارش.
- سهمیه رایگان نسخه ۱: **۳۰ دقیقه ابری در ماه** (قابل تغییر با Remote Config بدون انتشار کلاینت).
- پاسخ «سهمیه تمام شد» به‌صورت رویداد روی همان WebSocket می‌آید تا داور فوراً سوییچ کند.

### ۵.۳. STT Gateway
- همان الگوی چندتأمین‌کننده با Failover که قبلاً طراحی کرده‌ایم: جدول Providerها با اولویت قابل‌تنظیم از پنل ادمین، Health-check دوره‌ای، و سوییچ خودکار هنگام خطا/تأخیر بالا/گرانی.
- قرارداد داخلی واحد: ورودی = استریم PCM 16kHz + زبان‌های موردانتظار (fa,en)؛ خروجی = رویدادهای partial/final با برچسب زمانی. آداپتور هر Provider این قرارداد را ترجمه می‌کند.
- انتخاب Providerهای نسخه ۱ باید بر اساس یک بنچمارک داخلی فارسی انجام شود (مجموعه تست: گفتار محاوره، رسمی، مخلوط فارسی-انگلیسی، اسامی خاص). این بنچمارک یک تحویل‌دادنی مستقل قبل از توسعه است.
- صدا در Gateway **ذخیره نمی‌شود**؛ فقط عبور می‌کند. لاگ‌ها بدون محتوای صوتی/متنی‌اند (فقط متادیتا: مدت، Provider، تأخیر، نتیجه).

### ۵.۴. Polish Service (رزرو فاز ۲)
- در نسخه ۱ ساخته نمی‌شود، ولی قرارداد آن از حالا تعریف می‌شود: ورودی = متن خام + زمینه (نام برنامه مقصد، زبان، لحن انتخابی)؛ خروجی = متن صیقل‌خورده. قانون سخت: تغییر معنا ممنوع، فقط نگارش.
- کلاینت از نسخه ۱ یک مرحله «pipeline پس‌پردازش» خالی دارد که فعلاً فقط قواعد محلی سبک را اجرا می‌کند (بخش ۶) و در فاز ۲ گزینه ابری به آن اضافه می‌شود.

## ۶. پردازش متن فارسی (سمت کلاینت، نسخه ۱)

قواعد قطعی و بدون مدل زبانی که همیشه اجرا می‌شوند (هر کدام جدا خاموش‌شدنی):

1. تبدیل «ی/ک» عربی به فارسی و یکسان‌سازی نویسه‌ها.
2. نیم‌فاصله در پیوندهای شناخته‌شده: «می + فعل»، «ها»، «تر/ترین»، ضمایر متصل — با فهرست استثناها.
3. فرمان‌های نگارشی گفتاری: «ویرگول، نقطه، علامت سؤال، پرانتز باز/بسته، خط جدید، اینتر» → نویسه متناظر. فهرست فرمان‌ها دوزبانه (فارسی/انگلیسی) و قابل‌مشاهده در Studio.
4. فرمان‌های اصلاحی حداقلی: «اصلاح» (حذف جمله آخر)، «کلمه آخر را پاک کن»، «N کلمه آخر حذف شود» — فقط روی بافر جاری قبل از درج، نه متن درج‌شده.
5. اعداد: در حالت عادی به رقم؛ استثنا برای اعداد کوچک آغاز جمله (قابل تنظیم).

## ۷. امنیت و حریم خصوصی

- **حالت‌های موتور:** Cloud / Hybrid (پیش‌فرض) / Local-only. در Local-only حتی Health-check و آمار هم ارسال نمی‌شود.
- فایل‌های صوتی موقت رمزگذاری‌شده و پس از موفقیت حذف امن؛ حداکثر عمر فایل بازیابی‌نشده ۷۲ ساعت، سپس حذف خودکار.
- TLS برای همه ارتباطات؛ Pinning گواهی Gateway در کلاینت.
- تله‌متری فقط Opt-in و بدون هیچ محتوای متنی/صوتی: رویدادهای ناشناس (موفقیت/شکست درج، استراتژی استفاده‌شده، تأخیر، کرش).
- انطباق نمایشی: نشانگر میکروفون ویندوز به‌طور طبیعی روشن می‌شود و هرگز دور زده نمی‌شود.

| وضعیت | رفتار | بازخورد کاربر |

## ۱۰. به‌روزرسانی و انتشار

- به‌روزرسان داخلی Tauri با کانال Stable/Beta؛ دانلود بی‌صدا، نصب هنگام ری‌استارت بعدی Daemon.
- Remote Config (از سرور): سهمیه رایگان، لیست برنامه‌های RTL-مشکل‌دار، اولویت Providerها، پرچم قابلیت‌ها — همه بدون انتشار کلاینت قابل تغییر.
- امضای کد (Code Signing) اجباری از اولین نسخه عمومی؛ بدون آن، SmartScreen اعتماد کاربر عمومی را می‌کشد.

## ۱۱. نقشه راه فنی فصل ۱ (ترتیب ساخت)

| گام | تحویل‌دادنی | معیار پذیرش |
|---|---|---|
| ۰ | بنچمارک Providerهای فارسی + انتخاب دو Provider اول | گزارش مقایسه دقت/تأخیر/قیمت |
| ۱ | Daemon حداقلی: میانبر + ضبط + ابری + Clipboard | دیکته کار می‌کند، زشت ولی واقعی |
| ۲ | Gateway + Quota + Auth | کاربر واقعی با سهمیه |
| ۳ | Injector کامل (سه استراتژی + Snapshot + RTL) | درج مستقیم در Word، Telegram، Chrome، VS Code، Notepad |
| ۴ | Overlay زبان بدن + Tray + Silent Mode | حس محصول |
| ۵ | موتور محلی + داور + صف تأخیری | قول گم‌نشدن |
| ۶ | Studio: Onboarding + تنظیمات + History + لیست سیاه | نسخه Beta عمومی |
| ۷ | پردازش فارسی قطعی + سخت‌کردن کارایی | انتشار ۱.۰ |

هر گام مستقلاً قابل تست با کاربر واقعی است.

## ۱۲. ریسک‌ها و پرسش‌های باز

**ریسک‌های فنی:**
1. **آنتی‌ویروس‌ها و هوک کیبورد:** هوک `WH_KEYBOARD_LL` و `SendInput` ممکن است توسط برخی آنتی‌ویروس‌ها پرچم شود. کاهش: امضای کد معتبر، ثبت در Microsoft، و مسیر جایگزین بدون هوک برای PTT (فقط Tap در صورت مسدودشدن).
2. **برنامه‌های Elevated:** درج در پنجره‌های Run-as-Administrator از پروسه عادی ممکن نیست (UIPI). تصمیم نسخه ۱: پشتیبانی نمی‌کنیم؛ سقوط به Clipboard + مستندسازی.
3. **کیفیت فارسی Providerها:** اگر بنچمارک گام ۰ نشان دهد هیچ Provider ابری فارسی قابل قبول ندارد، وزن معماری به سمت مدل محلی «دقیق» جابه‌جا می‌شود — این سناریو باید در گام ۰ تعیین تکلیف شود.
4. **بازی‌های تمام‌صفحه Exclusive:** Overlay دیده نمی‌شود؛ رفتار: فقط بازخورد صوتی اختیاری یا هیچ، درج در بازگشت به دسکتاپ.

**پرسش‌های باز برای تصمیم محصول:**
1. پرداخت بازار ایران (درگاه داخلی) در کنار پرداخت بین‌المللی — کدام در نسخه ۱؟
2. سیاست چندزبانه فراتر از فارسی/انگلیسی در نسخه ۱ یا فاز بعد؟
3. نام‌گذاری نهایی و بررسی برند «Zero» از نظر تعارض علامت تجاری.
