## ADR-001: معماری دو-پروسه‌ای (Daemon + Studio)
- وضعیت: تأیید
- زمینه: قول رم زیر ۵۰ مگابایت با WebView دائمی ناسازگار است.
- تصمیم: Daemon تمام-Rust بدون UI وب + Studio با Tauri فقط بنابه‌نیاز؛ ارتباط Named Pipe.
- پیامدها: پروتکل IPC باید نگهداری شود؛ در عوض کرش UI هرگز دیکته را نمی‌اندازد.

## ADR-002: هیبرید با پیش‌فرض ابری
- وضعیت: تأیید (تصمیم محصول)
- تصمیم: Cloud پیش‌فرض، whisper.cpp محلی به‌عنوان پشتیبان و حالت خصوصی؛ صف تأخیری وقتی هیچ‌کدام ممکن نیست.

## ADR-003: کلید Providerها فقط سمت سرور
- وضعیت: تأیید
- تصمیم: تمام STT ابری از Gateway عبور می‌کند؛ کلاینت فقط JWT دارد.

## ADR-004: استفاده از cpal برای ضبط صدا
- وضعیت: پیشنهاد
- زمینه: WASAPI مستقیم با windows-rs حدود ۳۰۰ خط کد COM ناامن نیاز دارد. cpal یک wrapper امن و تست‌شده روی همان WASAPI است.
- تصمیم: از cpal برای ضبط صدا استفاده شود. WASAPI زیرساخت اصلی باقی می‌ماند ولی از طریق cpal صدا زده می‌شود.
- پیامدها: کد ساده‌تر و پایدارتر؛ وابستگی اضافه. سایر APIهای Win32 (hotkey, tray, clipboard) مستقیم با windows-rs.

(تصمیم‌های بعدی را ایجنت هنگام برخورد به ابهام، به‌صورت «پیشنهاد» اضافه می‌کند و قبل از پیاده‌سازی تأیید می‌گیرد.)

## ADR-005: یادداشت محلی با SQLite + FTS5
- تاریخ: 2026-07-20
- وضعیت: پیشنهاد
- زمینه: Zero Notes به جستجوی تمام‌متن فارسی سریع نیاز دارد؛ تمام داده باید محلی باقی بماند (حریم خصوصی).
- تصمیم: SQLite با افزونه FTS5 برای جدول یادداشت‌ها، رمزنگاری با `crypto.rs` موجود. بدون وابستگی سروری.
- پیامدها: جستجوی فارسی کارآمد بدون سرور؛ FTS5 توکنایزاسیون فارسی را به‌اندازه کافی خوب پوشش می‌دهد. حجم داده محلی رشد می‌کند ولی تحت کنترل کاربر.

## ADR-006: سرویس ترجمه پشت gateway
- تاریخ: 2026-07-20
- وضعیت: پیشنهاد
- زمینه: ترجمه همزمان (fa↔en) به یک سرویس خارجی نیاز دارد؛ کلیدها طبق ADR-003 باید فقط سمت سرور باشند.
- تصمیم: افزودن ماژول TranslationProvider پشت gateway (الگوی مشابه STT) با سهمیه جداگانه `quota:translate:{userId}:{yyyymm}`.
- پیامدها: سیستم سهمیه به‌صورت تمیز گسترش می‌یابد؛ provider قابل تعویض (DeepL، Google، OpenAI).

## ADR-007: حالت جلسه + ترنسکریپت فایل + خلاصه‌سازی LLM
- تاریخ: 2026-07-20
- وضعیت: پیشنهاد
- زمینه: ضبط طولانی (۳۰–۶۰ دقیقه) به بافر قطعه‌قطعه رمزشده نیاز دارد؛ خلاصه‌سازی نیاز به LLM سمت سرور دارد.
- تصمیم: گسترش `buffer.rs` برای بافر قطعه‌قطعه رمزشده؛ خلاصه‌سازی LLM به‌عنوان قابلیت اختیاری Pro از طریق gateway.
- پیامدها: وابسته به فاز ۸ (Zero Notes) برای ذخیره‌سازی؛ هزینه LLM باید در سهمیه ردیابی شود.
